Order-source AI pilot — 2026-11-16

Status: implementation and offline regression validation complete; external activation NOT approved and NOT enabled. No actual AI API calls, live extraction accuracy claims, customer emails, payments, or customer data access.

User flow
- Existing /import-document reads PDF/photo text locally with bundled PDF.js/OCR. Standard spreadsheet reading remains available.
- Only an enabled, explicitly allowlisted account sees optional “Use AI to read this order”. It is unchecked, discloses OpenAI text transfer/retention, and is not remembered on reload.
- Selecting a source/worksheet or preparing a pasted order sends only its text to a new guarded mode on the existing extraction endpoint after opt-in. No mailbox access, original PDF/image upload, saved account data, signature or other documents sent to OpenAI.
- The server requests structured JSON, verifies value/evidence substrings against source, checks decimals and line totals, blanks unsupported values, and flags incomplete results and mixed currencies. Literal evidence matches do NOT prove correct semantic extraction. The customer must review every value and omission.
- Source quotes are viewable per field and retained with the existing browser recovery draft. No provider response is executed as HTML/code. Previous draft survives provider errors. No automatic retry.
- User confirmation and explicit Save Invoice still required. Reviewed import fields are not silently enriched from buyer/product masters at save. Existing Invoice→Packing flow copies shared facts; actual cartons/weights remain for user review. No AI tools, email sending, purchase, or document-writing access.

Operator activation — requires separate user approval for a new external service/cost
- Model: gpt-5.6-terra; fixed https://api.openai.com/v1/responses; store=false; structured output; reasoning low; max_output_tokens=8192; no tools, prior conversation, URL override or redirects.
- Set TRADE_PAPER_ORDER_AI_API_KEY securely on the existing service, never in source, logs, browser or chat. Use a dedicated project/key without opted-in data sharing.
- Set TRADE_PAPER_ORDER_AI_ACCOUNTS to explicitly approved test account IDs (no wildcard); set TRADE_PAPER_ORDER_AI_ENABLED=1 only after permission. Empty/missing settings fail closed.
- Limits: 20,000 UTF-8 bytes of source, 20 items, existing 5-page/8MB PDF limits, bounded provider response, timeout, durable SQLite reservation before each call. Requests, including failed/uncertain calls, capped at 3/account/day, 5 globally/day, 20 globally/UTC calendar month. Counts are serialized across processes in the shared data directory. Ledger contains account hash/day, not source or output.
- Current official price: $2 per million input tokens, $12 per million output tokens. Twenty modest orders should cost less than $5 in this limited pilot, but this is an estimate at current rates and request caps, not a provider-wide dollar billing guarantee. Other project usage, taxes and exchange rates excluded. No new plan, free-document allowance or customer pricing change.
- After activation, agent must run a small set of fictional English/Korean order PDFs, compare extracted values/omissions/quotes with ground truth and record actual provider token usage/cost. API account/model availability and live model accuracy remain unverified. User need not perform repeated tests.
- To disable this optional pilot, set TRADE_PAPER_ORDER_AI_ENABLED=0; standard import stays available. Do not disable live subscription payments.

Privacy
- store=false does NOT mean Zero Data Retention. OpenAI default abuse-monitoring logs may retain content up to 30 days, subject to exceptions. Public privacy notice and per-use opt-in disclose this; no claim of ZDR approval. Existing browser draft recovery and recipient/downloaded-copy boundaries remain.
